# Business Entity Resolution — Final Project README

## Problem Statement

Given three sources of business entity records (Source 1, Source 2, Source 3), the task is to determine which entities across sources refer to the same real-world business.

**For every Source 1 entity, predict its matching entity ID(s) from Source 2 and/or Source 3.**

If no confident match exists, the prediction should be empty.

Evaluation: **Macro F0.5** (precision-weighted harmonic mean — false positives are costly).

## Approach Summary

The solution is a **precision-first entity matching pipeline** with three stages:

### Stage 1: Text Normalization

- Lowercase all text fields
- Strip legal business suffixes (LLC, Inc, Corp, GmbH, Ltd, etc.)
- Standardize address abbreviations (St → Street, Rd → Road, etc.)
- Extract phone numbers and domain names as structured signals
- Produce both compact (no-space) and token (space-joined) normalized representations

### Stage 2: Candidate Blocking

Two blocking strategies reduce the search space from O(N×M) to manageable candidate pairs:

1. **Name block**: normalized compact name + country code
2. **Address block**: normalized compact address + country code

Explosion guards limit block sizes (max 50 pairs per key, max 10 targets per key) to prevent memory blow-up on common names.

### Stage 3: Similarity Scoring + Threshold

For each candidate pair:
- Country must match (hard filter)
- Compute name similarity: `max(ratio, token_sort_ratio)` via RapidFuzz
- Compute address similarity: same approach
- Final score = `0.6 × name_score + 0.4 × address_score`
- Apply penalties for street-number mismatches (−0.35) and domain/phone conflicts (−0.50)

**Decision threshold (best validated config):**
- Accept if top score ≥ 0.85 (unconditional), OR top score ≥ 0.75 with margin ≥ 0.05 over second-best
- Otherwise: predict empty (no match)

## How to Reproduce

### Requirements

```bash
pip install pandas numpy rapidfuzz
```

### Run the pipeline

```bash
# Best validated submission (Day1 #3 method)
python submission_03_pipeline.py

# Precision-first margin threshold (Day1 #4 method)
python submission_04_pipeline.py
```

### Validate a submission

```bash
# Fast validation (recommended)
python validate_fast.py submissions/day1/submission_03.tsv

# Original validation script
python validate_local.py
```

---

## Key Rules Observed

- **No graph transitive closure**: A→B and B→C does NOT mean A→C
- **No external data**: Only provided dataset files used
- **Country hard filter**: Records from different countries are never matched
- **Precision-first**: Better to predict empty than predict wrong
